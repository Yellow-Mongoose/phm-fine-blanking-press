# 가이드북 실행 및 검증 계획

기준: 로컬 「소성가공 예지보전 AI 데이터셋 가이드북.pdf」.
아래 쪽수는 책에 인쇄된 쪽수이며 PDF 뷰어 페이지는 1을 더한다.

## 최신 구현 상태

데이터는 `C:\Users\pds20\datasets\kamp\fine-blanking-press\raw`로 이동되었다.
2~6단계 코드는 `press_pipeline.py`에 구현했으며 실제 실행 명령은 README를 따른다.
실제 CSV로 guide/strict 전처리 실행과 합성 데이터 테스트 3개를 통과했다.
0.1초와 다른 시간 간격이 정상 599개, 이상 20개 관측되므로 정확한 시간 단위
예측 실험에서는 간격 분포와 수집 특성을 추가 확인해야 한다. 자동 보간은 하지 않았다.
TensorFlow가 현재 인터프리터에 없어 학습·모델 재로딩은 아직 실행 검증하지 않았다.
아래의 초기 상태 기록과 옛 경로 예시는 최초 점검 당시의 기록이다.

## 1. 최초 확인 결과

- 현재 실행 코드는 없고 Git 추적 파일은 README.md 하나다. 로컬 전체 브랜치 이력에서도 데이터 커밋은 발견되지 않았다.
- 실제 CSV 폴더: `C:\Users\pds20\phm-fine-blanking-press\3. 소성가공 예지보전 AI 데이터셋\3. 소성가공 예지보전 AI 데이터셋`.
- `press_data_normal.csv`: 20,000행, Equipment_state가 모두 0.
- `outlier_data.csv`: 600행, Equipment_state가 모두 1.
- CSV의 첫 열은 저장된 인덱스다. `pd.read_csv(..., index_col=0)`으로 읽으면 가이드의 5개 열이 남는다.
- 두 파일 모두 빈 셀은 0개다. 저장 인덱스를 제외한 동일 행은 정상 데이터에서 1개, 이상 데이터에서 0개 확인했다. 숫자 변환, NaN/무한대, 시간 간격 등의 상세 검사는 구현 단계에서 추가한다.
- 현재 기본 Python은 3.13.1이다. 모델 학습 및 패키지 설치는 아직 수행하지 않았다.

## 2. 데이터 위치와 Git 관리

권장 원본 위치는 저장소 밖의 `C:\Users\pds20\datasets\kamp\fine-blanking-press\raw`이다.
이 폴더에 두 CSV를 두면 코드 저장소와 물리적으로 분리할 수 있다.
현재 파일은 이동하지 않았으며 현재 위치에서도 실행할 수 있다.
저장소 안에서 관리하고 싶다면 `data/raw/`가 대안이다. 이 경로도 Git에서 제외했다.

실행 코드에서는 `DATA_DIR` 환경변수나 `--data-dir` 인자로 경로를 받도록 구현한다.
예를 들어 현재 위치를 사용하는 PowerShell 설정은 다음과 같다.

```powershell
$env:DATA_DIR = 'C:\Users\pds20\phm-fine-blanking-press\3. 소성가공 예지보전 AI 데이터셋\3. 소성가공 예지보전 AI 데이터셋'
```

이 변수는 앞으로 작성할 코드에서 직접 읽어야 하며 `.env` 파일도 자동으로 로드되지는 않는다.

`.gitignore`에 현재 원본 폴더, `data/`, CSV 및 주요 데이터 형식, 가상환경,
`artifacts/`, `outputs/`, `runs/`와 학습 가중치 형식을 제외했다.
모델 구조·학습·평가 코드는 GitHub에 관리하고 학습된 가중치는 로컬 `artifacts/`에 저장한다.
노트북을 커밋할 때는 원본 행을 포함한 셀 출력을 지운다. 강제 추가(`git add -f`)는 제외 규칙을 우회한다.

커밋 전 확인:

```powershell
git status --short
git diff --cached --stat
git ls-files -- '*.csv' '*.parquet' '*.npy' '*.npz'
```

마지막 명령의 결과가 없어야 한다. 코드에 데이터 값을 복사하거나 새 형식으로 저장하는 경우도 별도 확인한다.

## 3. 실행 순서

1. **독립 환경 준비** (18~22쪽)
   - 가이드 재현을 우선하여 Python 3.9.7, NumPy 1.20.0, TensorFlow 2.7.0을 기준으로 별도 환경을 만든다. 현재 Python 3.13 환경에 섞어서 설치하지 않는다.
   - pandas, matplotlib, seaborn, scikit-learn, Jupyter/ipykernel도 필요하다. 설치 패키지명은 `scikit-learn`, import명은 `sklearn`이다.
   - 가이드에서 버전을 고정하지 않은 패키지는 해당 환경에 호환되는 버전을 확인하고, import와 `pip check` 성공 후 실제 버전을 잠근다. 가이드의 설치 목록만으로 완전히 같은 환경이 보장되지는 않는다.
   - 우선 CPU로 짧게 실행한다. TensorFlow 2.7.0 배포 파일과 설치 조건은 [PyPI](https://pypi.org/project/tensorflow/2.7.0/)에서 확인한다. 최신 환경으로 옮기는 실험은 별도로 기록한다. Windows GPU 지원 조건은 [공식 설치 문서](https://www.tensorflow.org/install/pip)를 따른다.
2. **데이터 로딩 및 품질 확인 코드 작성** (22~27쪽, 부록 56~63쪽)
   - 두 파일 존재, 20,000/600행, 5개 열, 0/1 라벨과 숫자 자료형을 검사한다.
   - TimeStamp 파싱, 날짜 범위(정상 2022-07-12, 이상 2022-07-17), 시간순 정렬 여부와 0.1초 수집 간격을 점검한다.
   - 결측·중복·무한대와 센서 통계를 기록하고 세 센서의 시계열 그래프를 그린다.
   - 첫 재현에서는 정상 중복 행을 임의 삭제하지 않는다. 정제 실험에서는 처리 근거와 변경된 표본 수를 별도 기록한다.
3. **전처리와 데이터 분할 구현** (27~34쪽)
   - 입력은 AI0_Vibration, AI1_Vibration, AI2_Current 세 열이며 모두 절댓값으로 변환한다. Equipment_state는 입력에서 제외한다.
   - 정상 앞 15,000행을 학습, 나머지 5,000행과 이상 600행을 검증·평가 후보로 둔다. 학습 원본으로만 MinMaxScaler를 fit한다.
   - 가이드 코드대로 sequence=20, 라벨 위치 `index + sequence + 100`, 반복 범위 `range(N - sequence - 100)`을 사용한다.
   - 예상 입력 shape: 학습 `(14880, 20, 3)`, 검증 `(1180, 20, 3)`, 평가 `(4180, 20, 3)`.
   - 검증은 정상 880개+이상 300개, 평가는 정상 4,000개+이상 180개다. 학습 중 val_loss 계산에는 정상 검증 880개만 사용한다.
4. **모델 작성 후 짧은 실행** (34~36쪽)
   - Encoder LSTM 64→32, RepeatVector(20), Decoder LSTM 32→64, TimeDistributed(Dense(3)).
   - 입력과 복원 목표 모두 X이며 loss=MSE, Adam 학습률 0.001, batch_size=128이다.
   - 먼저 1~3 epochs로 학습·예측·오차 계산·저장까지 오류 없이 연결되는지 확인한다. 이 결과로 성능을 판정하지 않는다.
5. **본 학습과 임곗값 결정** (35~38쪽)
   - 최대 800 epochs, ReduceLROnPlateau(factor=0.7, patience=50), EarlyStopping(min_delta=0.00001, patience=120, restore_best_weights=True)를 기준으로 실행한다.
   - 난수 seed, 패키지 버전, 분할 방법, 실제 학습 횟수 및 소요 시간을 기록한다.
   - 가이드는 윈도 전체 평균이 아니라 마지막 시점의 3개 센서에 대한 평균 제곱 재구성 오차를 이상 점수로 쓴다.
   - 검증 데이터로 임곗값을 결정한 후 고정한다. 테스트 데이터로 임곗값을 조정하지 않는다.
6. **평가 및 저장·재로딩 검증** (38~40쪽)
   - 혼동행렬, accuracy, precision, recall, F1, 정상 오탐률을 기록한다.
   - 가이드 참고값: TN=3922, FP=78, FN=26, TP=154, accuracy=97.51%, F1=74.76%. 임곗값 약 0.0035는 참고값이며 다시 산정한다.
   - 모델, scaler, 임곗값, 센서 순서, 절댓값 처리와 sequence 설정을 함께 로컬 artifacts에 저장한다. 다시 로드하여 동일 입력에 대한 점수·판정이 유지되는지 확인한다.
   - 코드, 환경 명세, 원본 행이 없는 요약 지표만 GitHub에 올린다.

## 4. 재현과 성능 검증에서 구분할 사항

- **겹치는 시계열 구간:** 가이드는 윈도를 만든 뒤 검증/평가를 나누므로 경계의 두 윈도가 원본 19개 시점을 공유한다. 엄격한 검증 실험에서는 원본 시간 구간을 먼저 나누고 각 구간 안에서 윈도를 만들며 미래 라벨도 같은 구간에 속하게 한다. 이때 표본 수와 결과는 가이드와 달라진다.
- **10초 사전 예측의 해석:** 가이드는 미래 라벨을 연결하지만 정상 파일은 전부 0, 이상 파일은 전부 1이다. 모델은 입력 재구성을 학습한다. 이 실습 결과만으로 정상→고장 전환 10초 전 탐지 성능이 입증되지는 않는다. 이를 검증하려면 고장 전후의 연속 기록과 실제 고장 시각이 필요하다.
- **임곗값 코드:** `precision == recall`인 첫 지점을 찾는 코드는 교점 부재 등에 대한 방어가 필요하다. precision/recall은 thresholds보다 원소가 하나 많으므로 임곗값 대응에는 `precision[:-1]`, `recall[:-1]`을 쓴다. 교점이 없으면 검증 F1 최대 지점 등의 명시적 대안을 사용하고 재현 코드와의 차이를 기록한다.
- **PDF 코드 전사:** 스마트 따옴표, 들여쓰기, 누락되어 보이는 뺄셈 기호를 확인한다. 절댓값 처리는 `df[use_col].abs()`로 표현할 수 있다. 부록의 일관성 지수는 `len(df)/len(df)` 형태여서 실제 자료형 오류를 검증하는 코드로 보완해야 한다.
- **결과 비교:** 학습 난수와 실행 환경에 따라 수치는 달라진다. 가이드 수치 일치만을 합격 기준으로 삼지 말고 데이터 누출 여부, 오탐·미탐과 재실행 가능성을 함께 확인한다.
