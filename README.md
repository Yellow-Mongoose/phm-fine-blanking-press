# KAMP 이상 탐지 노트북 사용법

센서 데이터로 정상 상태를 학습하고, 이상 상태를 얼마나 잘 찾는지 평가하는 노트북 3개입니다. **처음에는 LSTM-AE 하나로 시작하고, 아래 순서대로 실행하세요.** 세 파일의 사용 방법은 같습니다.

## 1. 어떤 파일을 열면 되나요?

| 파일 | 설명 |
| --- | --- |
| [KAMP_LSTM_AE_v4_Colab.ipynb](KAMP_LSTM_AE_v4_Colab.ipynb) | LSTM-AE: 시간 흐름을 학습해 입력을 복원하는 모델 |
| [KAMP_ModernTCN_v4_Colab.ipynb](KAMP_ModernTCN_v4_Colab.ipynb) | ModernTCN: 합성곱으로 시간에 따른 패턴을 학습하는 모델 |
| [KAMP_PatchAD_P2_4_v4_Colab.ipynb](KAMP_PatchAD_P2_4_v4_Colab.ipynb) | PatchAD: 데이터를 크기 2·4의 작은 구간으로 나누어 학습하는 모델 |

각 파일은 독립적으로 실행할 수 있습니다. 세 모델을 비교하려면 같은 데이터와 실험 조건으로 각각 실행하세요. 모델을 바꿀 때는 해당 노트북을 열고 별도 런타임에서 시작하면 편합니다.

## 2. 시작 전 준비

1. 사용할 `.ipynb` 파일을 Google Colab에서 엽니다. VS Code를 사용한다면 **Colab 서버의 GPU 커널**에 연결합니다.
2. GPU는 **L4 또는 T4**로 설정합니다. 현재 코드는 CPU나 다른 종류의 GPU에서는 실행을 중단합니다.
3. 이 폴더의 CSV 두 개를 Colab 서버의 `/content`에 업로드합니다. 웹 Colab에서는 파일 패널을, VS Code에서는 **Upload to Colab**을 사용합니다.

```text
/content/press_data_normal.csv
/content/outlier_data.csv
```

`/content`는 내 PC가 아닌 **Colab 서버의 폴더**입니다. 노트북을 열었다고 CSV까지 자동 업로드되는 것은 아닙니다. `DATA_PATH`에 Windows의 `C:\Users\...` 경로를 넣지 마세요.

CSV는 원본 그대로 사용하세요. 코드는 정상 20,000행·이상 600행과 정해진 중복 행 수를 검사합니다. 필요한 열은 `TimeStamp`, `AI0_Vibration`, `AI1_Vibration`, `AI2_Current`, `Equipment_state`입니다. 임의로 행을 삭제하거나 다른 데이터로 바꾸면 검사를 통과하지 못할 수 있습니다.

## 3. 처음 실행할 때 바꿀 설정

노트북의 **「3. 실행 옵션」 코드 셀**에서 아래 항목을 확인합니다. 셀은 코드를 실행하는 한 칸을 뜻합니다.

```python
STORAGE_MODE = 'drive'      # Google Drive에 결과 백업
DATA_PATH = '/content'     # CSV 두 개를 올린 폴더
RESUME_EXPERIMENT_ID = ''  # 처음 실행할 때는 빈 문자열
RUN_SMOKE = True           # 먼저 3회 시험 학습
USE_WANDB = False          # 처음에는 외부 실험 기록 서비스 사용 안 함
```

**원래 파일은 `USE_WANDB = True`이므로, 처음에는 직접 `False`로 바꿔 주세요.** 그러면 `.env`나 W&B 계정 없이 학습할 수 있습니다. `MODEL`은 각 노트북에 맞게 정해져 있으므로 그대로 둡니다.

| 설정 | 기본값 | 뜻 |
| --- | --- | --- |
| `N_TRIALS` | `8` | 서로 다른 설정으로 학습할 후보 수 |
| `MAX_EPOCHS` | `800` | 후보 하나당 최대 학습 횟수. 조건에 따라 먼저 종료될 수 있음 |
| `BATCH_SIZE` | `128` | 한 번에 처리할 데이터 묶음 크기 |
| `PLOT_EVERY` | `10` | 학습 그래프를 갱신할 학습 횟수 간격 |

처음에는 나머지 값을 그대로 두고 **시험 학습까지만** 실행해도 됩니다. 시험 학습은 본학습과 별개이며, 시험 학습의 가중치를 본학습에 이어 쓰지 않습니다.

## 4. 실행 순서

각 코드 셀 왼쪽의 실행 버튼 또는 `Shift + Enter`로 실행합니다. **앞 셀이 끝난 뒤 다음 셀을 실행하세요.**

1. 맨 위의 **Google Drive 연결 셀**을 실행하고 계정 연결을 완료합니다.
2. **「1. 자동 환경 준비」 → 「2. 라이브러리」**를 실행합니다.
3. 위에서 수정한 **「3. 실행 옵션」 → 「4. 저장·인증·데이터 경로」**를 실행합니다. 출력되는 **실험 ID와 결과 위치**를 메모하세요.
4. **「5. 데이터 준비 함수」부터 「실행 1」 직전까지 모든 코드 셀**을 차례로 실행합니다. 모델과 학습 기능을 정의하는 단계이므로 출력이 없어도 정상입니다.
5. **「실행 1 — 데이터 준비」**를 실행합니다. 데이터 크기와 분할 표가 나오면 다음으로 진행합니다.
6. **「실행 2 — 선택적 3 epoch 실행」**을 실행합니다. `epoch`는 학습 데이터를 한 차례 학습하는 단위입니다. 사용법을 확인하려면 여기까지 실행하고 멈춰도 됩니다.
7. 실제 학습을 하려면 **「실행 3 — 8후보 본학습」**을 실행하고 완료될 때까지 기다립니다. 기본 설정은 최대 8개 후보 × 800회이므로 시험 학습보다 오래 걸립니다.
8. **「실행 4 — 고정된 후보의 Test 평가」 → 「실행 5 — 그래프와 결과 위치」** 순서로 실행합니다. 중간에 추가 정보 표시 셀이 있으면 함께 실행하면 됩니다.

## 5. 결과 확인과 다운로드

Drive 저장을 선택했다면 결과는 다음 위치에 있습니다. `<모델>`은 `lstmae`, `moderntcn`, `patchad` 중 하나입니다.

```text
내 드라이브/KAMP_comparison_v4_validloss_all/<모델>/<실험 ID>/
```

| 파일 또는 폴더 | 확인할 내용 |
| --- | --- |
| `test/comparison.csv` | 최종 성능 비교표. 가장 먼저 확인할 파일 |
| `test/*.png` | 학습 곡선과 평가 그래프 |
| `final_candidate/` | 최종 선택 모델의 가중치와 전처리·추론 설정 |
| `selection.json` | 어떤 후보가 선택됐는지와 해당 설정 |
| `trials_summary.csv` | 학습 후보별 결과 요약 |

비교표는 **저장 시점 3개 × 이상 판정 기준 2개 = 6행**입니다. `primary=True`가 기본 대표 결과입니다. `test_precision`은 이상이라고 판정한 것 중 실제 이상 비율, `test_recall`은 실제 이상 중 찾아낸 비율, `test_f1`은 두 지표를 함께 보는 점수입니다. 이 세 지표는 높을수록 좋습니다. `test_available=False`이면 해당 판정 기준을 구하지 못한 것이므로 비어 있는 지표를 0점으로 해석하지 마세요.

ZIP으로 내려받으려면 맨 아래 **「결과 ZIP 만들기」** 셀에서 다음처럼 바꾸고 실행합니다.

```python
MAKE_RESULTS_ZIP = True
DOWNLOAD_IN_BROWSER = True  # 웹 Colab에서 바로 다운로드
```

VS Code에서는 `DOWNLOAD_IN_BROWSER = False`로 두고 출력된 ZIP 파일을 Colab 파일 탐색기에서 다운로드합니다.

`STORAGE_MODE = 'local'`을 선택하면 결과는 `/content/KAMP_results_v4_validloss_all/<모델>/<실험 ID>/`에 저장됩니다. 이 경우 맨 위 Drive 연결 셀은 건너뛸 수 있습니다. **로컬 저장은 내 PC 저장이 아니며, 런타임이 삭제되면 사라지므로 종료 전에 다운로드하세요.**

## 6. 중단된 학습 이어서 실행하기

1. 같은 노트북을 열고 이전과 **같은 GPU 종류**에 연결합니다. 예: 이전이 T4였다면 다시 T4.
2. 이전 결과가 저장된 Drive를 연결합니다. 필요한 입력 파일도 다시 업로드합니다.
3. 「3. 실행 옵션」에 이전 실험 폴더 이름을 그대로 넣습니다.

   ```python
   RESUME_EXPERIMENT_ID = '이전에_출력된_실험_ID'
   ```

4. 학습 설정과 코드를 이전과 같게 두고, 위 실행 순서대로 다시 진행합니다. 저장된 상태가 있으면 복원하고, 본학습이 이미 끝났다면 Test 단계로 진행할 수 있습니다.

결과 폴더 전체를 보관하세요. 가중치 파일만으로는 학습 재개 상태를 모두 복원할 수 없습니다. 백업되지 않은 마지막 진행분은 다시 실행될 수 있습니다.

코드·데이터·학습 설정을 바꾸어 새 실험을 시작할 때는 **커널을 다시 시작하고 `RESUME_EXPERIMENT_ID = ''`로 설정**하세요. 같은 커널에서는 이 값을 비워도 기존 실험 ID가 유지될 수 있습니다. 런타임 자체를 삭제한다면 먼저 임시 파일을 백업하세요.

## 7. W&B 기록 사용하기 (선택)

W&B는 학습 기록을 온라인으로 확인하는 선택 기능입니다. `.env` 파일에 `WANDB_API_KEY=본인_API_키`를 저장해 `/content/.env`로 업로드한 뒤 `USE_WANDB = True`로 설정합니다. `ENTITY`는 본인 계정 또는 접근 권한이 있는 팀으로, `PROJECT`는 기록할 프로젝트로 바꾸세요. API 키를 노트북 코드에 직접 적지 말고 `.env`는 결과 폴더 밖에 보관하세요.
